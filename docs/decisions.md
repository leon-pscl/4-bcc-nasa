# Decisions

One entry per decision that changed the plan after it was first written. `instructions.md`
already reflects each one; this file records why. Add an entry whenever a section 5 default
or a contract changes. Newest last.

| ID | Date | Decision | Why |
|---|---|---|---|
| D1 | 2026-11-13 | **Fresh start.** Branch `pascual` reset at `a5e4cfb`; the first attempt stays in history at `82a4528` for reference only. Only `sample-data/` was restored from it. | The first attempt had grown too far from the plan to fix in place. |
| D2 | 2026-11-13 | **Own drag-to-draw handler; no Leaflet.draw.** | Leaflet.draw keeps its own copy of the shapes, which has to be synced with React state both ways. It hasn't had a release since 2018, its toolbar fights the spec, and it doesn't wrap longitudes. |
| D3 | 2026-11-13 | **bboxfinder-style map toolbar:** a stack at the top-left (zoom +/−, Draw area, Delete area), 44 px buttons, `z-index: 1000`, rendered outside `MapContainer`. Overrides `frontend-tasks.md` 5.3, which put zoom at the bottom-right. | The owner's choice of look. The first version was invisible because it had no z-index and sat under Leaflet's map layers. |
| D4 | 2026-11-13 | **"Today" is the latest data date**, never the server clock. `end` after it is a 400. | Closes `frontend-tasks.md` B3. A browser in Manila can be a day ahead of a UTC server, and "this month vs median" must not shift with time zones. |
| D5 | 2026-11-13 | **`FIRMS_DAY_RANGE_MAX = 5`.** | FIRMS's page says 1..10, but a real request with 10 was rejected. Transactions are counted per day either way, so this only doubles the number of requests. |
| D6 | 2026-11-13 | **Two regions, Southeast Asia and the Amazon, kept in `config/regions.json`,** with starter areas under 500,000 km² for the default view and the "Jump to" picker. Users analyze areas inside the regions only. | FIRMS charges per day, not per area, so a few large regions are the cheapest coverage. Both are among the most fire-active regions on Earth. Regions as data mean adding one needs no code change. |
| D7 | 2026-11-13 | **History from FIRMS yearly country files; the area API only for the current year and daily updates.** Each region downloads every country its box touches and clips to the box. | About 650 transactions per region instead of about 14,000. Including every touched country avoids parts of a box silently showing zero fires. |
| D8 | 2026-11-13 | **Parquet datasets partitioned by region and year, processed with DuckDB or one partition at a time.** | The two regions likely hold tens of millions of detections, too many to load whole into pandas. Partitions let a daily update rebuild only the current year. |
| D9 | 2026-11-13 | **Calibration keyed by satellite:** C3 has `region`, `platform` and `reference` (`SNPP`). | MODIS is near end of life and S-NPP has flown since 2011. NOAA-20/21 can be calibrated to the same reference later without changing C4 or the app. |
| D10 | 2026-11-13 | **Data version** (C7) in every API response, as an `ETag`, and as the key of a server-side response cache. `/health` reports freshness per region. | Repeated queries (starter areas, watchlist checks) become instant, caches refresh themselves after each pipeline run, and stale data is visible. |
| D11 | 2026-11-13 | **CI on GitHub** (`pytest`, `npm run check`) on every push; merge only when green. Reports name commits and tests, and give the numbers each stage asks for. | On day one, a fix was reported but never committed, and tests that checked nothing passed while k was 4× wrong. CI makes "tests pass" visible without running anything locally. |
| D12 | 2026-11-13 | **Not built yet:** database server, Kubernetes, microservices, job queue, user accounts. | Data is read-only for users and has one writer, the pipeline. If the app outgrows one machine, the data moves to object storage and the API runs as read-only copies: a migration, not a rewrite. |
| D13 | 2026-11-13 | **ESLint** (with `typescript-eslint` and `jsx-a11y`) as the linter. | It's on the approved list, and no linter was installed after the reset, so `frontend-tasks.md` 6a's ESLint-or-oxlint question no longer applies. |

| D14 | 2026-11-14 | **Shrinkage calibration.** `k_month = (viirs + 30*k_tile)/(aqua + 30)`, `k_tile = (viirs_tile + 30*k_region)/(aqua_tile + 30)` (`SHRINK_M = 30`). | Raw ratios gave tile-month k of 0.53–26.19; marginal months dominated. m=30 gave the best held-out r/bias/MAPE of {0, 30, 100, 300}. The 0.53–26.19 was across all tile-months; per-tile medians ranged 1.56–26.19. |
| D15 | 2026-11-14 | **NOAA-20/21 continuity after S-NPP ends.** No SNPP on a date -> NOAA-20×k(NOAA-20→SNPP), else NOAA-21×k, else Aqua×k gap fill. New C4 bases `viirs_noaa20` / `viirs_noaa21`. `latest_date` is the last harmonized day. | S-NPP ends 2026-11-02; "this month vs median" would otherwise rest on nothing. Overlap: NOAA-20 k≈1.017, NOAA-21 k≈1.041 (≈1:1). |
| D16 | 2026-11-14 | **500,000 km² limit stays** (`MAX_AREA_KM2 = 500_000`); the map card shows the warning again. | O1 closed by the owner. Keeps the map under `MAX_MAP_CELLS`; matches the starter-area design. |
| D17 | 2026-11-14 | **Key status (O2) uses `/mapserver/mapkey_status/?MAP_KEY=...`.** Reports `current_transactions` / `transaction_limit` / `transaction_interval`; logged (numbers only) before long runs. | The documented `/api/map_key_status/{key}` path returns 400 "Invalid API call." and the working page uses `/mapserver/mapkey_status/?MAP_KEY=`. The key is never logged or printed (instructions.md §3, rule 8). |

| D18 | 2026-11-14 | **Symmetric sensor-outage exclusion in validation (`monthly_sql`).** A day where exactly one of Aqua/SNPP read at least one cell-day in the region is dropped from BOTH sides of the ratio (Aqua-down days: 2020-08-18..2020-09-02, plus 31 other days in 2012-2026). VIIRS months no longer keep the old MODIS-only exclusion alone; the S-NPP sum now counts only non-outage days too. | Before this, Aug 2020 read as Aqua x k = 4,438 vs VIIRS = 14,291 (-69%); much of the gap was Aqua simply not reporting (0 cell-days region-wide for 14 days while SNPP read thousands). After: VIIRS = 7,133 over the common days, bias -37.65%. Validation years after the fix (and the file re-ingest): 2020 -9.83% -> -8.59%, 2021 now -2.46%; full rerun lands -4.56% aggregate bias over held-out years. |
| D19 | 2026-11-14 | **New `/api/series` endpoint (the seam view).** Monthly raw Aqua / S-NPP / NOAA-20 / NOAA-21 cell-days, Aqua x k, the harmonized sum, the switch_date, the outage-day list since the switch, and an area-validation block (Pearson r, bias %, per-year bias of the overlap months, excluding outage days on both sides, VIIRS >= 10 cell-days/month). Region-wide outage days; bbox or point. | A teammate's prototype asked for a seam chart Aqua-vs-VIIRS to sanity-check the harmonization; the numbers must come from the same definitions as the rebuild-time validation. |

| D20 | 2026-11-14 | **Terra geo-located MODIS covers pre-S-NPP Aqua outages (basis `terra_gapfill`).** Days where Aqua cell-days region-wide fall below 10% of their trailing 30-day median (2003-2011, patchy Aqua) are filled with Terra x k_terra fitted against Aqua over 2003-2011; the C4 gapfill rules are unchanged. | Aqua read 0 over the region on some pre-2012 days (or collapsed to a handful), terra-missions were still up; without a MODIS source for those days the harmonized series has a hole before the S-NPP era. |
| D21 | 2026-11-14 | **Cover classes C9 IGBP mapping:** 1-5 = forest, 12/14 = farmland, 6-11 = other_vegetation, 13/15/16 = other; 17 water and 255 fill are excluded from counts. Fires labelled with cover of year(D)-1; 2024 granule for 2025+; 2002 for 2003 if needed. `cover=all|forest|farmland|other` on calendar/summary/map/hotspots/series/exports; `all` is the default. | Land-cover is a reading aid, not a filter for the burn-area math itself. Year-1 labelling avoids a granule vintage mismatch (a fire in Jan 2013 is on 2012 cover, yearly granules lag). |
| D24 | 2026-11-14 | **Cover source is MCD12Q1 (500 m, AppEEARS), not MCD12C1 (0.05 deg CMG).** C9 stores region-tagged cells; percentages are shares of *land* pixels (QC==0 only, D25); HDF not required; rasterio is a dev-only dependency. **Cover stability audit (2015-2024)**: cells whose majority class changed, per consecutive-year window: 2015-16 2.74%, 2016-17 2.67%, 2017-18 2.43%, 2018-19 2.33%, 2019-20 2.40%, 2020-21 2.56%, 2021-22 2.72%, 2022-23 2.41%, 2023-24 2.43%; 2015-2020 average 2.51% change vs 2021-2024 average 2.53%. The 2021+ layers are not abnormal; the year(D)-1 rule stays, with the 2024 map used from 2025 on. | AppEEARS delivers the full 2002-2024 series in one request; per 0.05-degree cell, the 500 m pixels tell the cell's true land mix instead of a CMG majority guess. |
| D25 | 2026-11-14 | **QC filter = `QC == 0` only (confident classified land) in cell_cover.** Pixel counts summed per cell exclude all QC != 0 (unclassified, misclassified/omission/backfill) and water/fill (17, 255). Aggregation matches the MCD12Q1 Statistics CSV to within ~1-3k pixels per class; the QC-dropped pixels are mostly class 11 wetlands (22k px) and class 13 urban (200k px). | The Statistics CSV itself proves the trusted-land denominator is the right one; the V6.1 QC backfills and climate-relabelled forest pixels would not reflect the ground truth we want for a present-day fire baseline. |
| D22 | 2026-11-14 | **Ingest de-duplicates on uid (SP preferred); write_partition aborts on staging/selected row mismatch.** `QUALIFY ROW_NUMBER() OVER (PARTITION BY uid ORDER BY CASE WHEN processing = 'SP' THEN 0 ELSE 1 END) = 1` in ingest, and every partition write now counts rows staged vs rows selected (raises, leaves existing partition intact). | The manual FIRMS archives carried duplicate byte-identical rows; stale year partitions had to be hand-republished. A wrong count now aborts loudly instead of silently truncating. |
| D23 | 2026-11-14 | **typical_year_error_pct = median |bias %| across held-out complete years** (default 2018-2021, 12 held-out months each). `/api/series` reports it (plus `fit_years`, `in_sample`, per-year months, `held_out_months`, and `outage_days` now clipped to the switch date and 2026-11-02). | Gives the UI a single honest number for the calibration uncertainty on pre-2012 years; S-NPP-planned end makes "outage" meaningless after it. |
